**You are running inside the thing you are fixing.** Beyond the template's rule: never restart the `agentorc-agent` / `agentorc-ui` user units, never create or kill `ao-*` tmux sessions, never edit `~/.claude/settings.json` or `~/.claude.json`. `pdm run test` (private tmux sockets, a temp `AGENTORC_HOME`) and `scripts/look_home.py` are the only ways you exercise the host agent. **A change to a page is verified by you, before its PR (design §4.9b, TD-291).** A PR that changes anything under `src/agentorc/ui/` is run first on a scratch home: `pdm run python scripts/look_home.py` in your worktree stands up a host agent and the UI from it, on a home under `/tmp`, a tmux server and a port of their own, with fixture sessions and a fixture board; it prints the URL, and SIGTERM or Ctrl+C tears it all down. Drive the page in headless Chromium under Playwright, installed at `~/ao-shots/pwlib` (`PYTHONPATH=~/ao-shots/pwlib ~/.local/share/agentorc-venv/bin/python <your script>`): load, wait for the scripts and the terminal, read values, press, screenshot. The PR's body carries a **UI check** heading, one line per check (what the change says, what was read), and its screenshots are committed as `docs/mockups/reviews/<date>-td<n>-<what>.png`, cropped to the change, at most four; a page PR with no UI check is not ready to merge. What a browser cannot settle — whether a layout or a wording is what the design means — is an `ask` to `{techlead}` before the merge (`ao msg --kind ask --about TD-NNN {techlead} "…"`) naming the screenshots and the §4.5 / §4.5a section and mockup; a *does not match* is fixed before the merge. What only the live copy shows is a `watch` line on `docs/user_attention.md` naming what to read: the member that next reads the board with the change's commit live (`ao promote status`) makes it read-only — a headless GET, no press, no `ao` verb that acts on a session of the live home, nothing under `~/.agentorc` — and closes it with what it read, or ledgers what is wrong. What is left for Paul is a **look, and a look is mail** (design §4.9b, §4.10 *A look*), sent after the merge — its first paragraph the one thing that is Paul's to judge, then what was checked and by whom, and the screenshots with `ao msg --shot` — in one of three cases: every check held, or the techlead said *matches* — **nothing is sent**, the UI check is the record; the techlead answered *not written* with a lean — `ao msg person --kind steer --default "Works" --bound 43200 --about TD-NNN "…"` naming its reply — the bound in seconds, no shorter than a night — which lapses to *Works* with no press; nobody leaned, or neither the scratch home nor a read of the live copy shows it — `ao msg person --kind ask --answer "Works" --answer "Not right: <what>" --about TD-NNN "…"`. A *Works*, a **Go with it** or a lapse closes it and nothing more is owed; a *Not right: <what>* is ledgered as an entry of its own and its outcome reported. No board line is written for a look.

**The gate here.** `pdm run test` and `pdm run lint` before the PR; `python3 scripts/check_cadence.py --pr N` exit 0 before the merge (capture the exit code: `| head` hides a FAIL); then `ao pr held N` (the held paths are `.agentorc.yml`'s `held:`; the path is *The path* above). `org.yml` is not in the repo and never yours to change. `gh pr edit` fails in this repo — use `gh api -X PATCH repos/eyecantell/agentorc/pulls/N --input -`. Merge with `gh pr merge N --squash`, never with `--delete-branch` from a worktree, and never delete a branch another open PR is based on (GitHub closes the stacked PR and its base cannot be changed afterwards).
