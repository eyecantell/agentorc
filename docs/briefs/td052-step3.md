**Build, in this PR:**

- **The `wait` RPC** in the host agent, with exactly `ao wait`'s semantics today — `scope` (`controlled` = the sessions whose `controllers` name the caller, the default; `all`), the wake vocabulary of `wake_digest`, the **complete snapshot compared against the per-caller cursor on disk under `waits/`** (a cursor that cannot be read means *unknown* and wakes on everything in scope; a first wait records and wakes on nothing), the changed records returned, `timeout`. `ao wait` becomes a thin call to it. A `wait` **runs on its own connection** and is **dropped the moment that connection closes** — a CLI killed mid-wait (Ctrl-C) must leave no ghost wait that is charged a wake and hands the mail to nobody; `_handle_conn`'s cleanup must cancel it. `wait` is a read: not in `ACTING_RPCS`, never gated.
- **`wait` returns on new mail too**: unread entries in the *caller's own* inbox that its cursor has not seen. The cursor already keeps mail that arrived mid-turn for the next wait (it is a snapshot comparison), so no second mechanism.
- **The wake decision.** A per-session **`mail_decided`** watermark (a home-owned field on the record — add it to `HOME_OWNED` and the ownership test will tell you if you forgot): the id (or `at`) of the newest entry any **wake** has covered. When a session is **reachable** — in this step, *blocked in `wait`*; hook-confirmed `idle` is the doorbell's moment and belongs to step 7, so structure the decision as one function step 7 can call, and do not ring anything — the host agent looks at the unread mail newer than the watermark: if there is any and the budget holds, it spends **one** unit, returns the wait, and advances the watermark to cover everything it returned, however many messages; if the budget is spent, the mail lands, the wait does not return for it, and **the watermark does not move**. A `wait` returning for a member's change with new mail alongside is a **free** wake: it returns both, advances the watermark, and is recorded as *not charged* — step 5 measures these separately, so record them. The decision is **re-taken on every host-agent tick** while a session stays blocked in `wait`, so a budget refilled by the rolling window wakes it then, not at its timeout.
- **The budget as placeholders**: `WAKE_BUDGET: int | None = None` (unlimited until step 6) mail-caused wakes per `WAKE_WINDOW` (a `timedelta`), in `mail.py` beside the others. Every decision is **recorded on the record** — a bounded list of `{at, cause: "mail" | "member", charged: bool, covered: N}` — because that record is what step 5 reads. **Exhaustion is visible**: the record's `mail` marks (`Session.mail_marks()`) say the budget is spent, and the `msg` RPC's reply to a sender says so when the addressee's budget is spent at send time. **A person's act refills it in full** — a `send` with no caller, a person's `msg` (reply or not), a `decide` on its permission — and *nothing a session does does*: no controller's send, no turn mail did not start. Opening Focus (`seen`) or reading its inbox as a person refills nothing.
- **The line on every `ao` reply.** Every `ao` command's output ends with `[agentorc] you have N unread messages — run ao inbox` while the calling session has unread mail, with ` (wake budget spent)` appended while it is. The cheapest honest way: the host agent adds a small `mail` field to the **response envelope** of every RPC whose caller is a session with unread mail (`_dispatch` knows the caller); `LocalClient` surfaces it; the CLI prints the line once, after the command's own output, on every command including a refusal. It types nothing and starts nothing.
