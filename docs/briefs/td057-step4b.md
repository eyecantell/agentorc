### 4b.2 — the home's intent reaches the node's replica, and the node's own arrivals reach the home

- **The push.** Since 4a a home-owned edit on `id@host` is sent to the node in the same call, and refused while the host is unreachable — so the replica rarely disagrees. It still does after a home restored from an old store, after a `_route_act` whose second half failed, and for one field a node needs on every reply: the **unread count** (step 5 decision 1 — a read the node serves alone carries no unread line). Build the general push the design asks for (*The home pushes each node its records' policy fields as they change*): a link method home → node, `intent {records: [{id, host, <the HOME_OWNED policy fields>, unread}]}`, sent once after a snapshot is taken and again when a home-owned field or the unread count of that host's record changes; the node applies it with `models.apply_home` — every address in it written in the node's form (`_to_host`), the three union-merged fields left to their merge — and keeps `unread` as a hint (never in `inbox`: the mailbox stays the home's) that its own `_dispatch` reads for the mail line. **Never push `inbox`, `outbox`, `threads`, `wakes` or a message body to a node.** Decide whether 4a's per-call push for the four edits stays (it is what makes an edit on an unreachable host a refusal rather than a divergence — keep that property either way) and say so.
