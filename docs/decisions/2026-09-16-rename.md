# ADR 2026-09-16: rename the project — `shiftlead` is the leading candidate

Status: **open — not decided.** `shiftlead` leads; Paul asked for time to think on it
(2026-09-16). This records why the name has to change, the test a name must pass, what was
considered and why each fell, what a rename touches, and the decisions that are Paul's. The work
is ledgered as TD-060. Nothing is renamed by this document.

**Claimed 2026-09-17, ahead of the decision (Paul):** PyPI `shiftlead 0.0.0` — an empty
placeholder whose README says so and points at this repo — and the GitHub org `ShiftLead`.
Both are reversible; neither commits the project to the name. Domains not yet registered.

## Context

The name `agentorc` is in use by another project (found by Paul, 2026-09-16; which project, and
on which registry, is not recorded here — TD-059 step one is to name it). The project has been
renamed once already: it was `sessionherd` for the first day of design and became `agentorc` on
2026-09-04 *to sit beside [cmdorc](https://github.com/eyecantell/textual-cmdorc)* (README). So
the current name was chosen for a family resemblance, and a rename gives that up — see
"What is lost".

Two import packages carry the `-orc` suffix, not one: `agentorc` and `sessionorc` (the neutral
tmux/host layer that never imports `agentorc`, design §4.3). A rename has to decide both.

## The test a name must pass

Drawn from how the candidates failed, in the order they mattered:

1. **Free where it is installed and hosted** — PyPI, npm, crates.io, and the GitHub org/user.
   A free domain is the least of these; `directr.me` was free while npm and GitHub were not.
2. **Spellable after hearing it once.** `directr` becomes *director*, `dunamoo` becomes
   *dynamo*, `teem` becomes *team*. A name that must be spelled aloud every time fails at the
   only moment word of mouth happens.
3. **Not `agent` + an authority word.** `agentorc`, `agentdirector` and `agentboss` are all
   taken, the last by two unrelated projects within three months. That is the obvious move in
   this niche and everyone is making it; the next one will be taken too.
4. **Searchable.** A search engine must not autocorrect it to something else, and the results
   it competes with should not be other software.
5. **Fits once explained**, even if it does not explain itself.

## Why `shiftlead`

- **It is the product's own word.** The glossary decided on 2026-09-16 that the session which
  coordinates a team's workers is the **lead** (TD-055: `orchestrator` → `lead`). The project
  would be named after its central role, with no new vocabulary.
- **The metaphor is the job.** A shift lead does not do the work: they assign it, check in,
  notice who is stuck, and hand over at the end of the shift. Unattended overnight teams are
  shifts. `director > lead > worker` reads naturally under it.
- **No "agent", no "AI".** It will not date, and it is outside the namespace everyone else is
  mining.
- **Availability surprised Paul, and it is real as of the check date.** The nearest neighbour is
  `ntnusky/shiftleader`, a dormant Puppet management dashboard — different name, different
  field.

Against it, stated plainly:

- **It does not say what it is.** It needs a tagline on every first screen. Draw that sentence
  from TD-059's survey — what this does that `agentboss` and the §3 tools do not.
- **Search results are retail job postings.** Not competing software, so `shiftlead cli` finds
  the project — but the bare word will never be ours.
- **A natural phrase can be taken tomorrow.** A coined word cannot. If the decision is yes,
  claim the PyPI name and the GitHub org the same day, before any code moves.
- **The short CLI is lost** — see the next section.

## What is lost

- **`ao`.** It appears as the command in every brief, the skill text, the design and the
  ledger, and as the `ao-` prefix on every session id and tmux session name
  (`sessionorc.naming.PREFIX`). `sl` is unusable (the steam-locomotive typo command, widely
  installed) and `shift` is a shell builtin. Paul's view (2026-09-16): the CLI is not typed
  often enough for a short form to matter. That settles the *command*; it does not settle the
  **session-id prefix**, which is data, not a command — see Decisions.
- **The `-orc` family** with `cmdorc`. If that pairing still matters, the rename is the moment
  to say so; nothing else in this document weighs it.

## What a rename touches

Measured on `origin/main` at `8bd21b9`, case-insensitive `git grep`:

- **`agentorc`: 1,110 occurrences in 93 tracked files.** tests 276, `src/agentorc` 128,
  `docs/design.md` 106, `docs/briefs` 65, `docs/technical_debt.md` 58, `docs/decisions` 50,
  the archive 42, mockups 36, `src/sessionorc` 28, memories 26, README 16, glossary 13,
  the board 11, CLAUDE.md 11, `pyproject.toml` 9.
- **`sessionorc`: 260 occurrences in 56 files.**

By kind, from cheapest to most careful:

1. **Text** — docs, comments, the README. Mechanical. *Dated records stay as written*: ADRs,
   the ledger archive and memories describe what was true when they were written, and a
   rewritten ADR is a false one. One line at the top of the README and the design says
   "was `agentorc` until <date>".
2. **The distribution and its entry points** (`pyproject.toml`): the project name, five
   scripts (`agentorc`, `ao`, `agentorc-agent`, `agentorc-hook`, `agentorc-ui`) and the
   adapter entry-point group `agentorc.adapters` — a third-party adapter would register
   against that group name, so it is an interface (no external adapter is known; not searched for).
3. **The import packages** — `src/agentorc`, `src/sessionorc`, and every import of them.
4. **Names that live on a machine, outside the repo.** These are what make the rename a
   migration and not a search-and-replace:
   - the state directory `~/.agentorc/` (`agent.sock`, `sessions`, `events`, `runs`, `waits`,
     `attachments`, `claude-hooks`, `recent_dirs`, `org.yml`, `hosts.yml`, `profiles.yml` as
     listed on kmaster 2026-09-16, plus `person_inbox.json` per `sessionorc.paths`) and
     `AGENTORC_HOME`;
   - the environment variables `AGENTORC_SESSION` (16 uses — it is how the hook and every
     `ao` call find the calling session's id, so it sits in the environment of each running
     session), `AGENTORC_HOME`, `AGENTORC_TMUX_SOCKET`,
     `AGENTORC_PERMISSION_WAIT`, `AGENTORC_TICK`, `AGENTORC_PROFILE`;
   - the systemd user units `agentorc-agent.service` and `agentorc-ui.service`, and the
     installed venv `~/.local/share/agentorc-venv`;
   - the per-repo config file `.agentorc.yml` (19 references), which lives in *other* repos;
   - the `[agentorc]` prefix on lines the tool prints into sessions (9) — briefs and skill
     text teach sessions to recognise it;
   - the `ao-` session-id prefix: every record in `~/.agentorc/sessions`, every tmux session
     name, every `controllers:` list and every mail address is keyed on an `ao-…` id.
5. **Other repos.** samscrape, contractmatch and dev-cadence each carry 7 occurrences in the
   same three synced files (`docs/cadence.md`, `docs/cadence-changes.md`,
   `scripts/cadence_hooks.sh`) — canonical in dev-cadence, so one edit there and a sync.
   `~/.config/dev-cadence/repos.txt` names the repo path. pneuma-ops has none.
6. **GitHub** — `eyecantell/agentorc`. A repo rename redirects; whether the project moves to a
   `shiftlead` org is a separate choice.

**The hazard in (4):** live sessions hold `AGENTORC_SESSION` in their environment and hooks
resolve `agentorc-hook` from the unit's PATH. A rename applied under a running team breaks the
hooks of every session already started. The rename lands with **no team running**, the agent
and UI stopped, and the state directory moved once — or read from both names for a stated
window.

## Decisions that are Paul's

1. **The name.** `shiftlead`, or keep looking.
2. **`sessionorc`.** It is the neutral layer and "becomes its own repo only when a second
   consumer exists" (README). Options: leave it (the name is not the taken one, and it is
   never typed by a user); rename for consistency (`shiftlead.core`, or a sibling word);
   or fold it to a subpackage. Leaving it is the cheapest and keeps one `-orc` alive.
3. **The session-id prefix.** Keep `ao-` as an opaque historical prefix (zero migration, and
   ids are data), or change it and migrate every record, controller list and mail address.
   Recommendation: keep `ao-` — nothing a person reads depends on it meaning anything.
4. **The CLI command.** `shiftlead` alone, or also keep `ao` as an installed alias through a
   transition so existing briefs and muscle memory do not break on day one.
5. **Compatibility window.** Read `~/.agentorc`, `.agentorc.yml` and `AGENTORC_*` as fallbacks
   for a stated period, or a clean cut with a one-time `migrate` command. A clean cut is
   reasonable while there is one user.
6. ~~Claim the names now?~~ **Done 2026-09-17** — PyPI and the GitHub org (see Status). The
   domains remain.
