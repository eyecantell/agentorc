# ShiftLead — design history

The dated record of how [`design.md`](design.md) came to say what it says: decisions, reversals,
review rounds, live findings and Paul's words, by section, in date order. `design.md` is the
present-tense specification and states only what is true now; this file is where its history went
on 2026-09-22 (the design review, TD-109) and where every later change appends its dated fact.
Nothing here is a rule. Where a bullet and the design disagree, the design is current and the
bullet is what was true on its date.

The ADRs under [`decisions/`](decisions/) and the ledger ([`technical_debt.md`](technical_debt.md),
[`technical_debt_archive.md`](technical_debt_archive.md)) hold the reasoning behind the larger
decisions; this file points at them rather than repeating them.

## 4.1 Session substrate: tmux, one session per conversation

- undated (PR #17): Resume's supersede — closes the exited record and keeps it a day. The create-time supersede (below) extends it to a fresh start under the same name and goes one step further by forgetting rather than keeping.
- undated: `pipe-pane` continuous streaming to `~/.agentorc/runs/<session>-<created>.log` replaced tdgrind's per-tick snapshot.
- 2026-09-10 (§10 decision, §9 invariant 12): a name identifies one session within its scope (the repo, or the directory for a repo-less session).
- 2026-09-10 (TD-010 a): a live session with no tmux at all (`claude` in a VS Code terminal, found via Claude Code's registry `~/.claude/sessions/<pid>.json`) was shown as a read-only card.
- 2026-09-10 ([ADR herdr spike](decisions/2026-09-10-herdr-spike.md)): measured on herdr that a runtime holding the ptys itself must kill every session to restart and re-launch the tool with `--resume` once a client attaches — the reason tmux owns the processes; the same spike saw a `.bashrc` `cd` relocate every pane — the reason argv runs directly, never through the person's shell.
- 2026-09-11 (TD-030, all of it): every `ao` subcommand that takes an id accepts a bare name ("so nothing that worked before changes" — a full `ao-…` id still means itself); the create-time name rules landed: live holder refused with error data, exited/closed holder superseded and replaced in place with *previous run* as a new field, unrecorded tmux panes decided on tmux's own answer, the check locked on the scope. What was wrong before: the same `ao new` would refuse or suffix depending on the second it landed in (whether the tick had adopted a stale pane), and `-2` cards appeared for a name that was simply reused.
- 2026-09-13 (TD-036 step 1): the `controllers` field landed (§4.8's membership list).
- 2026-09-13: `team` and `project` badges landed (§4.9).
- 2026-09-17: Paul had the no-tmux read-only cards (TD-010 a) removed — a card for a session a person started by hand, outside agentorc, reads as being watched, and it offered nothing to do. The Org is what agentorc started or adopted; the registry is still read only for `occupancy` (§9 invariant 2).
- 2026-09-20 (TD-077 a2): the suspended exception designed and built — a holder a person suspended over an identity alarm refuses every `create` under its name until a person lifts it; the name check answers `suspended`.
- 2026-09-20: a team would not start because a brief had reached 16,194 bytes and tmux refused the argv ("command too long", about 16 KB). Fix: past 8 KB the argv goes to `launch/<tmux name>.sh` (mode 0700) exec'd under `/bin/sh` — the one exception to argv-runs-directly.

The host agent ignores that notification while its waiter is live.

- 2026-09-11 (cadence §3): the settings layer took on dev-cadence's one SessionStart runner line (`scripts/cadence_hooks.sh --session-start`). The pre-2026-09-11 per-hook block in a worktree's `.claude/settings.json` counts as wiring the hooks, so such a worktree runs only the hooks its block names until its branch carries the runner line.
- (TD-015): the pane classifier's shape was chosen after herdr's detector caught the trust dialog that no hook reports.
- (TD-032): an unattended worker whose pane was stood down by a Remote Control takeover sat twenty hours with its PR unmerged and nothing flagged it, because the pane read as `idle`; the screen rule that reads the takeover banner as `stalled?` followed.
- 2026-09-17: the **no live member** item was added to the Ready to close checklist, read from the control graph (`controllers`) so it covers a manager, a director and a hand-attached controller alike.
- 2026-09-20 (TD-080): *pushed* became one measure computed once by the host agent. Before, the card's *n unpushed* flag, the checklist, the Inbox row and `ao team stop --close` had three tests between them. What it replaced: *ahead of the upstream*, which is *unmerged* when the upstream is `origin/main` — a launch branch tracking `origin/main` and pushed to `origin/<branch>` at wrap-up read as *308 unpushed* for ever, and a row that is always there teaches a person to ignore the row.
- 2026-09-21 (TD-095 (e)): the unseen mark read *finished · unseen* until this date; Paul's decision renamed it *idle · unseen*, because *finished* is what a member that declared itself out of work is called (§4.9a), and this is a turn nobody has looked at, not a run that is over.

- 2026-09-24 (TD-072, the designer): Ready to close gains **mail read**; the **outcomes reported** row TD-079 built on 2026-09-20 is written into the list, where it had been missing.
- 2026-09-25 (TD-026, the designer; Paul's answer the same day): the `scheduled` state — a record with a launch record and no pane, created at `ao new --at` or the form's **At** field.

Until this date every `SessionStart` read `working`, and a one-press Resume with no prompt — the designer's record, 2026-09-25 14:06Z — sat `working (hook)` at an empty composer, headed for `stalled?` at `STALL_AFTER` and never rung by the doorbell, which rings a hook-confirmed idle only.

## 4.3 Adapter contract

- 2026-09-13: the word *turn* was taken from OpenAI's Agents API (ADR decisions/2026-09-13-openai-agents-api.md) because it named a split agentorc already had and could not say in a sentence: session durable, turn one piece of work. Send to `idle` starts a turn, to `working` steers it — one control, not two, because the difference is what the person is doing, not what the code does.
- 2026-09-14 (§4.10): `mail()` added to the adapter protocol; when an adapter has no native delivery path the core falls back to a pane write (a `send`), and §4.10's message/control line becomes a convention the adapter's brief keeps rather than a gate the host agent enforces.
- The adapter status table was written "at design time", each row to be verified before its adapter is built; Claude Code and `shell` were phase 1.
- 2026-09-23 (TD-122): `label` added to the contract (the tool's display name, for the chip), and `usage()` said to be called once per account and to carry every window the endpoint reports, a per-model weekly one labelled with the model.
- 2026-09-23 (TD-122, the build): `account_for(profile)` added to the contract as an optional method — the core cannot read a profile, so the adapter says which account the poll keys on; without it the poll keys on the profile, as before.
- 2026-09-24 (TD-035, the designer): the 2026-09-12 decision with Paul — tool-specific wiring of a repo's start hooks belongs in the adapter, not in the repo — written into the contract as *A repo's start hooks are every adapter's to run*: through the tool's start hook, else the runner at launch with its stdout prepended to the first prompt; the anchor check's source for another tool decided with that adapter (TD-112). Nothing to build until a second adapter exists.
- 2026-09-25 (TD-128, the designer): `spend(profile)` — per-turn tokens and cost from the tool's own records for a metered profile; the prices are the profile's, never the core's.
- 2026-09-25 (TD-128 reconciled, with Paul): `spend(profile, cursors)` with four token kinds — cache reads folded into input would report a bill several times the real one — read from a byte cursor per transcript across the profile's config directory, sessions agentorc did not start included.

## 4.4 Host agent

- Until 2026-09-20 the usage poll ran every minute; TD-087 moved it to five minutes because a minute buys nothing against a five-hour window while spending an allowance the tool itself shares. The stated cost: a session at its cap shows `limited` up to five minutes later rather than up to one.
- 2026-09-20 (TD-087): usage fetch failures gained a reason. Before, *rate-limited*, *no credentials*, *no network* and *no profile* were one silence, and the silence cost more than a missing chip: `limited` is read from the same reading, so a session at its cap was not marked while the endpoint refused us. The `Retry-After` from a 429 is honoured uncapped because "a server saying *an hour and a half* knows something our ceiling is guessing at"; our own doubling stops at an hour.
- 2026-09-20 (TD-087): the usage reading moved to `usage.json`. It had lived in memory, so each promote forgot it and polled at once — eight times in one day. The first poll after a restart now waits until the held `fetched` plus the cadence.
- 2026-09-17 (TD-066): one oversize `list` reply took every `ao` on the machine down at once — asyncio's 64 KiB default frame was smaller than a day's records, and the raise happened in the reader, which could say nothing about the cause. `FRAME_LIMIT` (8 MiB) on every stream, and the agent refuses to write a longer line, followed.
- 2026-09-17 (TD-062): version skew became a designed property. Until then the install was editable, so a merged RPC change was live at once (one broke `ao progress` for every worker for 31 minutes); once promoted, a merged change reaches every session's `ao` before the running host agent knows it. Drop-unset-parameters on the client and drop-unknown-parameters (`ignored: [...]`) on the agent closed the window for existing methods; new methods or changed meanings still need the promotion. The `ignored` line is accumulated across every call a command makes "since the call that skews is rarely the last one"; a caller bug against a same-age agent looks identical from the client, so the agent's log line (naming the method) tells the two apart.
- 2026-09-21 (TD-063): `client.CALL_TIMEOUT` (120 s) added. The client had no bound on reading a reply, so an RPC that never returned blocked for ever: a CI job died after fourteen minutes naming the test *before* the one that stopped, and — the half that mattered — a live worker sat in `ao send` that never returned while its manager read it as `working`. The bound was applied one layer down from `_route_act`, where the reply is read; `AgentStuck` (a subclass) lets the one reconnecting caller distinguish a timeout (wedged agent, do not remake) from a drop (restart, remake).
- 2026-09-21 (TD-062 (c)): `built_from` / `started_at` added to `host`. A promote installed a wheel that was a flat `0.0.1` whatever it held, so nothing could say `main` had moved past the running copy. `pdm_build.py` now writes `sessionorc/_build.json`; `ao status -v` and `ao service status` print the commit and how far `origin/main` is ahead. An agent from before this reports *unknown*.
- Board write-back (Snooze / Done on `user_attention.md`) was proposed upstream as dev-cadence PR #83 (the carve-out from cadence §4's branch → PR rule) and depends on `nudge_user_attention.py --report --json` from dev-cadence PR #82. Not built in agentorc.
- 2026-09-23 (TD-069 step 3, grinder-ao-1): the write-back's RPC was built, `board_edit`. Until this date §4.4 said only that the host agent commits in *the main checkout*, and was silent on a checkout that cannot take the commit. The build refuses on four conditions: another branch checked out (the anchor works on branches in its checkout, so a commit there would land on someone's feature branch and ride its PR), a board with uncommitted changes, a git operation under way, and a line that no longer holds the item the person was shown. The Inbox's controls wait on the rows (draft PR #472), which the techlead held until this half existed (2026-09-23).
- 2026-09-23 (TD-122): the usage poll keyed on the account — once per `(adapter, account)` through one profile, cached per account, served under every profile sharing it, backed off per account, dropped when no live session's profile names it.
- 2026-09-24 (TD-120 step 2, the designer): the build line named as this repo's instance of the general `check` — one of the promote's three readings (§5 `promote:`, §6 *Promote*).
- 2026-09-24 (TD-069 step 4, the designer): the board write-back gains one **add** — *Put on the board* on an FYI row — the only line this system adds to a board, at a person's press; the rule *edits a pressed item and adds none* became *acts at a person's press and on nobody's behalf*.
- 2026-09-24 (TD-126, in a cloud session with Paul; Paul's shape decided that morning): the board write-back gained **Reply** — the person's words appended to the item's own line as ` — Paul, <date>: …`, one commit, and mailed as well only to a live session holding the lease on the line's reference, as a `handed` note. Paul's decision said *appended under the line*; the session found that dev-cadence's reader and the SessionStart hook match one `- [ ]` line each (`ITEM_RE`), so a second line under an item would be read by nothing, and the reply goes on the line itself. The item's `session`, `host` and `refs` were asked of the reader's JSON rather than parsed here (§4.4: never a second parser); the file writer is agentorc's own `sessionorc.board`, not the reader, which corrected the entry's point (c). The three standings — *still on*, *moved on*, *gone* — key on the lease first, so a reply reaches whoever holds the work even when the line's author is gone. Compared 2026-09-25 with the designer's PR #531, written the same afternoon before Paul's 12:30 standing decision: it puts the reply under the item and asks the reader to join continuation lines, mails a plain `note` with no outcome owed, and has no standing; the comparison also found that the SessionStart hook clips a due line at 200 characters (`MAX_ITEM_CHARS`), so on the line or under it the reader must print the reply for the hook to carry it — added to the ask on the board.

- 2026-09-25 (TD-128 reconciled, with Paul): a metered account's reading is a sum, not a poll — #547 said the home sums and not where the sum lives; decided: a daily ledger per account, `spend.json` beside `usage.json`, the cursors per host per transcript moving after the row is written, a rewritten transcript read from 0 with its ledgered turns dropped by `at` and, on a shared timestamp, by the entry's own id, kept thirteen months; a node's turns home as the `spend` link method with a reply, the reading back as a `usage` notification, the node's gate adding its own turns offline. The build is TD-151.

## 4.4a Home and nodes: one session graph across hosts (first half)

- 2026-09-16: section written. Phase 2 as first planned connected hosts hub-and-spoke (the UI host kept one ssh link to each host agent; host agents never talked to each other); that served a person and not a session acting across hosts. Mail was the first feature to need a cross-host session graph — Paul: *"we need to solve the cross-machine design now or the comms between agents are left funky"* (TD-057).
- 2026-09-16 (Paul): one host agent (kmaster) is home, the others are nodes; an agent whose `hosts.yml` names no `home:` is its own home, "which is phase 1 exactly".
- 2026-09-16 (Paul): *"won't the inability to reach home mean the UI will not render?"* — it would have; hence the offline fallback of `ao` / `ao ui` on a node to that node's own sessions.
- 2026-09-16 (Paul): the alternative offered — the laptop acting as its own home while offline — was rejected as the split-brain failure that rules out a mesh. Paul also ruled the hosted relay itself out of scope; the link is written as the protocol a relay would speak.
- 2026-09-16 (third review): field ownership by owner, never last write; a request's identity comes from the channel it arrived on, never from a field (the home ignores any host a client sends).
- 2026-09-16 (Sonnet review, narrowed by the third review): policies that stop run on the node, policies that start run at the home; the two accepted partition harms (extend does not resurrect; shorten is not seen until reconnect) were stated then.
- 2026-09-16: "When a host cannot reach home" written (Paul); spooling with the verdict returned later named as a possible later slice.
- 2026-09-17 (TD-057 step 2): the offline table written, "because step 2 builds the node before step 3 builds the link, so until then a node is *always* out of reach of its home and this table is its whole behaviour". Step 2 built and tested `models.apply_home` / `models.apply_node`; step 4 is what calls them across the link. The two decisions the rule did not make — reports refused rather than kept locally, and a person's mail refused too — were made here.
- 2026-09-17 (review of PR #198): three home-owned fields (`sends`, `seen_at`, `wake_refilled_at`) are merged, not overlaid, in both directions — an overlay "would erase the offline half and say it had worked".
- 2026-09-17 (TD-057 step 3a): the link's protocol decided "so both ends are written from one text": the forced-command bridge, `nodes:` in `hosts.yml`, frames with `re`, `FRAME_LIMIT`, `hello`/`ping`, `LINK_PING`, `LINK_SILENCE`, backoff 1 s → 60 s with jitter, the three diagnoses. The section was headed "What step 3a sends".
- 2026-09-17 (TD-057 step 4a): teams across hosts built — a team lands on one host (`host:` or the host the start runs on), the `host_dir` RPC (a `stat` link method) checks each checkout once before any name check, `ao team stop` degrades per member.
- 2026-09-18 (TD-057 step 5): mail across hosts built — a node forwards (`forward {rpc, params, caller, token}`), the home answers as `id@node`, replies re-addressed by `naming.readdress`; the doorbell is the forwarded `wait`, cancelled by token. From step 5 the offline table describes a node with its link down; with it up every refused cell is forwarded.
- Step 4b.1 (TD-057): permission prompts across the link built — a person's answer is `decide` routed as an act; the mark is `host_unreachable` on the view's `pending`, an overlay like `unreachable`; `decide` on a dropped link is refused like any act.
- Step 4b.2 (TD-057): decided there is no spool of hook events — on reconnect the node sends a full snapshot and that is the whole of it, since every consequence of a hook the home reads is a node-owned field and nothing at the home consumes an event. A live home record that disagrees on identity with a report is refused and logged. A node derives no reports while its link is down. Since 4b.2 a read the node serves alone carries the unread line from the count the home pushes with each record's intent.
- Step 4b.3 (TD-057): decided, and not built, that a node does not show the org (its `list`, `get` and UI stay this host's sessions with the link up too) — showing it would be a read across the boundary a person's forwarded request is held to (*Addresses*, PR #219). Built: the nightly backup tarball `backups/store-<date>.tar.gz` (first tick of each local date, off the loop, mode `0600`, temp name then rename, newest seven kept, a failure is a log line and tomorrow's retry); the `host_files {host, dir, paths}` RPC over the `files` link method with its `FILES_MAX` (16) / `FILE_CAP` (256 KiB) bounds and `modes.HOME_ONLY`.
- 2026-09-19 (TD-077; decided by Paul as the condition for TD-075's trial): `person: false` on a node's `nodes:` entry. Until this date a request arriving over a link with no `caller` was the person everywhere — designed, reviewed (#217, #219) and tested (`test_a_persons_forwarded_act_reaches_only_the_nodes_own_records`), right for a laptop and wrong for an agents-only container. A `nodes:` entry may carry `person:` from this date; an entry with neither `person:` nor `container:` keeps the behaviour until then (`person: true`).
- 2026-09-19: `{socket: <path>}` as a `link:` form (a container node's per-node socket at the home) noted as not yet built.
- 2026-09-20 (TD-052 step 7): a hook-confirmed idle is rung on the host whose agent holds the mailbox; a node, holding no inbox, rings nothing; across the link the ring will be that. The same step gave the node ownership of `wrapup_at` and `doorbell_failed`.
- 2026-09-21 (TD-057): a supersession on a node is done again at the home — the `supersedes` field `{id, mail, at}`, a same-id replacement taken whole except `suspended`, `superseded_by` for a record continued under another id.
- TD-066: the writing end refuses an oversize frame rather than leaving it to be discovered at the reading end.
