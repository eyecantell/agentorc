### 4.7 CLI

Package and canonical command: `agentorc`. The package also registers `ao` as an alias
(`ao status`, `ao new`, `ao shell`, `ao focus <name>`, `ao off --now`), a separate console-script
entry so anyone with a colliding `ao` can drop it without losing anything. The CLI is a thin
client of the host agent RPC — it never touches tmux itself (§9 invariant 1), with one read-only
exception: `ao focus <id>` and `ao new --attach` / `ao shell --attach` run `tmux attach` on the
session, the terminal's Focus screen, which creates, kills and types nothing (under `--json` the
attach argv is printed instead). That is how a session started from any terminal gets a
first-class card: `ao new --attach` where you would have typed `claude` (TD-010 b).

**Every subcommand:** takes `--json` and prints the RPC result with the ids the next call needs
(TD-018); every subcommand that takes an id also takes a bare name, resolved within the current
repo or directory (TD-030). The CLI reads the calling session from `AGENTORC_SESSION`, the
variable the hook uses (§4.2), and sends it as the request envelope's `caller` with every RPC
(TD-028): that is how a report lands on the right record and how the agent tells a worker acting
on another session from a person typing in a terminal (§4.8). The CLI follows herdr's JSON-first
CLI and skill file ([ADR](../decisions/2026-09-10-herdr-spike.md)).

**Naming.** `ao new <name>` applies §4.1's name rule and says so: a live holder is refused with
"`aotest` is running — `ao focus ao-agentorc-tests-aotest`, or pick another name" (exit 1, the
holder's id under `--json`); an exited or closed holder is superseded and the reply names the
previous run's log.

**Skills.** `ao --skill` prints the rules an agent driving `ao` from inside a session must
follow (TD-019); `ao --skill > .claude/skills/ao/SKILL.md` installs it in a repo (the New-session
install offer is phase 5). `ao team --skill` (TD-067) prints how to **stand a team up** — the
node, the project and the team definition, the roles and their briefs, and `ao team
list / start / status / stop`, each step a command. Both ship in the package (beside `skill.md`)
so they print anywhere `ao` runs, a container node with no checkout included, and both exit
during parsing, so they need neither a host agent nor `team`'s required subcommand. The README
points at them; there is no copy under `docs/`, which would drift.

**Explain.** `ao explain <id>` prints a session's screen, the rule that fires on it and whether
it applies; `ao explain --file` classifies a saved screen (TD-015).

**Transcript.** `ao transcript <id> [-n N] [--before OFFSET] [--raw]` prints what a session said
and did, without resuming it (§4.5 screen 9, TD-154): the last N turns (20) as the pane draws
them — `>` the prompt, the assistant's text, `⏺ Tool(first line)` per call with its result folded
to its first line, *thought · n lines*, *n subagent turns* — through the `transcript` RPC on the
record's host, a read gated by nobody. `--json` prints the adapter's neutral entries and the
offset `--before` takes for the turns before them; `--raw` prints the file's own lines instead,
the last N of them, for a reader that wants the tool's shape. A record with no tool session id is
refused with what it is (*a shell has no transcript*). A read-only verb, listed beside `tail` and
`explain` in `ao --skill`: what a manager reads before deciding a quiet member has stalled
(TD-091's moment), and what a person reads instead of Resume. Built (TD-165). The offset `--before` takes is given only
when an earlier prompt exists — the read goes back as far as the prompt before the ones it holds, so
*earlier turns* never opens on nothing but the tool's bookkeeping — and Claude Code's subagents,
which the tool now writes to their own files beside the session, are read from there and folded
under the Agent call whose id their record names (an older file's inline sidechain entries fold
under the Agent call before them).

**Reporting (§4.8, §4.9a).** Each is a small RPC on the calling session's own record — `--id`
for another's, since the channels are ungated:
- `ao progress claim TD-027`, `ao progress done TD-027 --pr 59`, `ao progress drop TD-027 --why "..."`, and `ao progress done TD-027 --pr 59 --slice` for a merged PR that leaves the entry claimed (§4.8, TD-321; built — TD-325 slices 1 and 2);
- `ao progress none --why "..."` — the session found no work it may pick (§4.9a, TD-053);
- `ao progress restart --why "..."` — the session's run is over and its lane is not (§4.9a *A run that ends with work left*, TD-083);
- `ao finding TD-029 --priority low`;
- `ao log "<line>"` appends one stamped line to the session's round log, `ao log --tail n` reads it back (§4.8 *A session's round log*, TD-175; built — TD-191): the manager's memory across runs, its own record only, never a report;
- `ao status -v` prints the same report line the card will, and `--json` the entries. A PR that
  is no longer open is marked as the card marks it, `TD-066 → #158 merged` (§4.5a card **report
  line**, TD-182; built — TD-193): the CLI reads `repos` once per call, and where that read is
  refused (a node offline) or holds no such PR the line is printed unmarked. The mark is in the
  text only; `--json` carries the entries as the record holds them. A claim holding slices prints
  them on a line of its own, *slices: TD-309 #1025, #1027*, a slice the tick derived marked `~`
  (§4.8, TD-325).
- `ao status -v` prints each record's context reading — *context 231k of 1M, bound 200k*, and *(over)* past it — and `--json` the `context` and `context_bound` fields (§6 rule 5, TD-188, TD-190).
- `ao status -v` prints a closed record's closer in the card's words — *closed by you*, *closed by manager-dc-1*, *closed itself*, *closed by the tick · team finished* — and `--json` the `closer` field (TD-262; built by TD-265 slice 2): a line under the record's, the words then the close's age.

With `--role`, the brief names the team's seat and manager, as a team start's does (TD-253).

**Membership (TD-036).** `ao control <controller> add|remove <session>…` edits membership from

verb of its own: `ao new <name> --team <team> --role <role>` starts the session, and a terminal
has no composer to fill.

**`ao pr held <n>`** (§4.9b *The reader*, TD-093): whether PR `n` waits for this session's reader —
the record's `review` checked against the PR's changed files, read with `gh pr view <n> --json
files,changedFiles` in the record's directory. `held` globs name paths from the repo root; `**`
spans directories, `*` and `?` stay inside one, a trailing `/` is everything under it, and
nothing else is special. The setting's defaults (`held` every PR, `bound` two hours) are filled

is not asked. A PR whose files cannot be read, or whose list `gh` returns short of its
`changedFiles` (one page of a large PR), is an error, never *not held*. `--id` asks about
another session's record. It is the author's own check, and the host agent never makes it. Under a flow with more than one review stage it prints the chain and whose turn it is, from the record and the home's `pr_reads` (§4.9c *A review stage any seat may hold*; built — TD-315 slice 4).

**`ao promote`** (TD-120 step 2; §5 `promote:`, §6 *Promote*; built 2026-09-27 — TD-132 slice 2, all
but `--sha`, `--back` and `clear`, below): the
press from a terminal. `ao promote [<repo>] [--sha <commit> | --back]` promotes the registered checkout —
the current directory's repo when none is named — to main's head, or to an older commit of main
for a rollback, through the `promote` RPC at the home, **refused to a session** (a person's own, as
`set_settings` is; a worker never promotes, CLAUDE.md) and refused, naming which, on §6's
preconditions (1) and (3); on (2) it says what the checks read and goes on, since the press is the
person's word; a repo whose live is main's head already is refused as having nothing to promote,
and one with no block says so. It returns once the run is started, with the log's path: the outcome is `check`'s
on a later tick, as §6 says, and for this repo the command's own host agent goes away under it.
`ao promote status` prints every promotable repo's readings — *agentorc · live 485d28b · main
9c1e0f2, 3 ahead · checks green · auto off*, in flight or failed with the log — and `--json` the
`promotes` field of `host`. `ao status -v`'s build line stays: it is this repo's `check` read from
the client's side, and the one line a session may read. **The rollback** (TD-212, designed
2026-09-28; built 2026-09-29 — TD-226): `--sha <commit>` takes a
commit's hex, in full or a prefix of seven or more that names one, never a branch, a tag or
`HEAD~n`, and **`--back`** is the commit that was live before the last
promote that concluded, so putting the live copy back takes no looking up. §6 *A rollback* says
what is refused (a commit that is not on main, one that is live already, a run in flight), how
the commit reaches `run`, and that the automatic promote then waits for the person. It prints
*rolling back `<repo>` to `<sha7>` from `<sha7>`*, what the checks on that commit read, and the
log's path; `ao promote status` then reads *agentorc · live 485d28b, rolled back from 9c1e0f2 ·
main 9c1e0f2, 3 ahead · checks green · auto on · held*. **`ao promote clear [<repo>]`** is Dismiss
from a terminal: it clears a failure standing, or a rollback's hold when no failure stands, because the page may be the
thing that is broken. Dismiss's half is the `clear_promote` RPC, a
person's own as `promote` is; both are home edits a node forwards or refuses (§4.4a).

**`ao doctor`** (TD-111; designed 2026-10-09, built by TD-465): one read-only command that runs the
checks the ledger keeps finding live — *found live: hooks that did not fire, a tmux server replaced
under the agent, a usage endpoint refusing, a node linked but behind, a wheel older than `main`* —
a line each with a verdict, and repairs nothing. It gathers what five commands already print (`ao
promote status`'s build line, `ao identity`'s mode and alarms, `ao org check`'s lacks and warnings,
`ao host status`'s link and build per node, `ao gate`'s reading per profile) and adds the three
probes nothing prints today: the hooks, the tmux server, and each profile's credentials and usage
endpoint. Each check is one line in the words `ao org check` uses — *ok: …*, *warning: …*,
*lacking: …* — a warning being a reading that may be meant (a build held behind `main` by a
rollback, an endpoint rate-limited), a lack one that is not; and every lack names, in the line, the
command or the step that cures it, since the command itself never does. The checks, in order:

- **agent** — the host agent answers, its version, and this repo's live build against `main`
  (`host.promotes`, §6 *Promote*): *ok: agent — 0.3.1, live 485d28b = main*; *warning: agent —
  live 485d28b, main 9c1e0f2, 3 behind · auto off* (the policy may hold on purpose, §6 *A
  rollback*). With no host agent answering the command stops here, exit 3 as every `ao` call:
  nothing below can be read without it.
- **tmux** — the server's pid, start time and cgroup, read by the host agent (`#{pid}` from
  `display-message`, `/proc/<pid>` for the rest), against the server it first read (the identity
  tick's re-read, §4.8a, which today keeps only the current one; the first read is kept for this): *ok: tmux — server 41022 since Tue 07:02, …/tmux.scope*;
  *lacking: tmux — server replaced under the agent: was 41022, now 58190 (restart the host agent)*
  (kmaster's was, 2026-09-20); *lacking: tmux — no server*.
- **hooks** — the settings layer (§4.2): for each profile, its layer files (one per launch shape — plain, `+cadence`,
  `+unattended`) are there and name a hook command that resolves (`agentorc-hook` on `PATH` or beside the interpreter); for each live agent
  session, its state's `confidence` is `hook`, with the age of its newest hook event; and the queue
  (`events/<session>.jsonl`) holds no line the tick has not applied. *ok: hooks — 4 sessions fed by
  hooks, newest 12s ago*; *warning: hooks — ao-agentorc-grind-w1 scraped for 40 min* (a session the
  hooks stopped feeding); *lacking: hooks — layer grind+unattended.json names no hook command that resolves*.
  **`--probe`** goes further: it launches a scratch session of each profile — or the one named,
  `ao doctor hooks --probe grind` — under its layer, in a temporary directory, with no prompt, waits
  for its SessionStart to write the record, up to 30 s, and kills it: *ok: hooks — probe grind:
  SessionStart in 2.1s*, or *lacking: hooks — probe grind: no hook in 30s* with the pane's last
  lines. A probe is a launch of the tool, so a login must be there, and it creates a session: it is a
  person's own, refused to a session as `ao new` on another is, and its record is deleted when the
  probe ends, never a card.
- **identity** — the mode, the detached-process check and the alarms standing (§4.8a): *ok:
  identity — enforce, detached-process check on*; *warning: identity — 2 alarms standing (`ao
  identity`)*.
- **profiles** — each profile of `profiles.yml`: its config dir, its credentials (`.credentials.json`
  there, the refresh token not expired), then the usage endpoint's answer — the host agent's last
  reading when it is younger than the poll, else one request, one per account (§4.2a): *ok: profile
  grind — credentials good, usage 5h 23% · week 61%*; *warning: profile grind — usage rate-limited,
  retry in 40s*; *lacking: profile grind — no credentials (log in: `CLAUDE_CONFIG_DIR=<dir> claude`)*;
  *lacking: profile grind — usage endpoint error*. A metered profile is never polled (§4.2a): *ok:
  profile grind-api — metered, key set*, or *lacking: … — no key*.
- **nodes** — each linked node (`host.links`): its link and its build against the home's wheel, the
  reading `ao host status` prints: *ok: node contractmatch — link up, build 0.3.1+g485d28b = home*;
  *lacking: node contractmatch — link down: never linked (`ao host up contractmatch`)*; *lacking:
  node contractmatch — build 0.3.0 behind the home's 0.3.1 (`ao host rebuild`)*. No node: *ok: nodes
  — none linked*.
- **org** — `ao org check`'s reading, each of its lacks and warnings on a line of its own, *ok: org —
  n teams* when it is clean; and `settings.yml` and `hosts.yml` parse: *lacking: settings.yml — line
  12: …* in the reader's own words.

Then *n lacking, n warnings* or *ok: n checks*, and exit 1 on any lack. `ao doctor <check>…` runs
only the named checks. `--json` is `{ok, lacks, warnings, checks: [{check, verdict, text, …}]}`,
each check carrying its raw reading beside its text (`tmux.pid`, `profiles[].usage.reason`, …). On a
node, the checks that read the home — the build against `main`, org, nodes — say *home only* and
count as neither; the rest read the node. **Where it lives:** a never-gated **`doctor`** RPC on the
host agent gathers the host-side readings (tmux, hooks, identity, profiles, nodes, the two files) in
one call, so a session may run the plain command — a lack is nothing it could not learn by trying,
and the command writes nothing; org and the build line are the client's own reads, as `ao org check`
and `ao promote status` already are, and `--probe` is the one part that acts. `ao --skill` lists it
among the read-only verbs: what a session runs before filing *found live*.

**`ao schedule`** (TD-026; §6 *Schedule*, §5 `settings.yml`; designed, not built — TD-133): with no

**`ao restart <session>`** (TD-246; §6 rule 2 *A person's restart*; built — TD-250): a person's press in the terminal — the `restart` RPC, refused to a session as
`set_settings` is — on a supervised `idle`, `exited` or `closed` record with a launch record:

**`ao new --at`, `ao at`** (TD-026; §6 *Start time*; built 2026-09-27 — TD-152): `ao new
