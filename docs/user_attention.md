# User Attention Board

Items that need the user to act or decide, plus in-flight work parked by a session. Sessions add entries **the moment they arise** and remove them when handled. Keep this file small — durable debt belongs in [technical_debt.md](technical_debt.md); this board is only "a human must act or decide."

All conventions — entry format and the `<host>` semantics, `Due:` dates and snoozing, the `Swept:`/`Swept-deep:` sweep stamps — live in [docs/cadence.md §3](cadence.md#3-never-strand-work). That file is SYNC (improvements reach every consumer on re-sync); this skeleton is SEED (yours, never overwritten), which is why the explanations do not live here (dev-cadence TD-17).

Format: `- [ ] YYYY-MM-DD (session <first-8-of-session-uuid> on <host>, or n/a) — what's needed. Context: TD-NNN / PR #N / branch. Due: YYYY-MM-DD.`

The mechanism, from `sessionorc.reports.derive` (`src/sessionorc/reports.py:65-107`): the checked-out branch yields `ProgressEntry(ref, status="claimed", pr=None)`; the `pending` re-check that lets a merge land after the session moves on takes only `(ref, pr)` **pairs**, and its caller filters on `if e.pr` (`src/sessionorc/agent.py:262-265`), so an entry with `pr=None` is dropped before the re-check list is even built; and the upsert (`Session.report_progress` -> `_upsert`, `src/sessionorc/models.py:220-240`) appends or replaces by `ref` with no delete branch anywhere. So a `tdNNN-*` branch that is created and abandoned *before* its PR exists -- which is what a grinder does the moment it finds a neighbour already holds that TD, i.e. correct behaviour -- leaves a `claimed` entry that nothing in the system can ever retire. Invariant 10 is not the escape hatch: a derived entry is replaced only when the session **declares the same reference**, and neither session has declared TD-395. A permanent false `claimed` means a worker that has finished everything still reads as having open work, so the nudge fires on every tick forever, telling it to continue or drop a TD it never held. That is the mirror image of the TD-026 gap this role was created to close, and it would arrive as noise rather than silence. Two cheap fix shapes, your call: have `derive` return the full set for a session so the tick can retire derived entries it no longer supports (declared ones untouched, invariant 10 intact), or carry branch-only claims with `pr=None` as provisional and expire them once the branch is gone.
